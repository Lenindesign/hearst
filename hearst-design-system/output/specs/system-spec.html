05 · Drawing HP-SYS-001 · Sheet 2

The change loop

Every change

  1. Request in plain English.
  2. Classify with the routing matrix.
  3. Preflight: git status, leave unrelated changes alone, read the code first, check for generated files, pick the smallest boundary.
  4. Edit only the owned files.
  5. Build and validate; generated files change only through scripts.
  6. QA at least three brands: the changed one, an adjacent one and an unrelated one (five in the pilot). Failures go back to the owner.
  7. Evidence: change, files, validation, brand coverage, known gaps.
  8. Release, then sync Figma and Pencil after merge.

Stop and ask when

  • A token key would be renamed or deleted.
  • A brand needs behavior tokens, variants or editorial modes can’t express.
  • A .pen file is corrupt or won’t open in Pencil.
  • Figma sync would touch variables outside the HDS collection.
  • The user’s own changes conflict with the edit.
  • It would deploy or push to production without being asked.

Pilot

Brands: cosmopolitan, car-and-driver, esquire, good-housekeeping, delish. Surfaces: article, home, card collection, right rail, newsletter, button, badge, nav, carousel, pagination, input.

07 · For the design system team

Findings

These come from comparing the charter, the runbooks, the skills and the vault. Nothing has been changed.

F1 · NEEDS A DECISION

Two places claim to own token values

The agent charter says Git token JSON is the source of truth. The Design Brain readme says to sync official token JSON and CSS from AI Enabler with design-system-token-sync. Fix: name one authority and describe the other as a sync target, in both documents.

F2 · DOC DRIFT

Eight roles in the charter, nine in the runbook, eight role skills

The charter lists 8 roles. The runbook adds a Grid System agent, for 9. The 8 role skills include Grid System but have no Publication Stylist skill. Fix: add Grid System to the charter and either add a hearst-publication-stylist skill or fold that role into Token Architect.

F3 · DOC DRIFT

Skills live in four places, and the charter names one

The charter says local agent instructions live in .cursor/skills/. Skills also live in .agents/skills/, hearst-design-system/.agents/skills/ and the vault (67 entry points), with no single index. Fix: add a skills registry to the charter: name, home, owner, and when to use it.

F4 · COVERAGE

28 metadata files for 148 component files

The review rules say new components need metadata and Storybook coverage. Some of the 148 files are sub-parts, so not every file needs its own metadata, but the gap is large. Next step: list the exported components without metadata and add them in small PRs.
