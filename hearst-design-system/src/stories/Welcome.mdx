## Product definition

Hearst+ is a reader-facing, cross-brand discovery product. It combines current editorial inventory from Lifestyle, Autos, Fashion & Luxury, and Enthusiast & Wellness into one personalized daily feed. It is not a publishing dashboard, CMS, or production identity service.

| Designers | Which HDS tokens, publication themes, layouts, and responsive rules own the interface |
| Developers | Which React component, provider, data contract, and source file implement the behavior |

## Catalog map

- **Start** explains the product, architecture, technology, and repository docs.
- **Product** renders the real Hearst+ feed and documents onboarding.
- **Foundations** records the HDS tokens, grid, color, and typography consumed by Hearst+.
- **HDS primitives** provides controlled states for the reusable UI building blocks used by the product.
- **Templates** tests the integrated feed at supported viewport ranges.
- **Delivery** covers design-to-code workflow, token publication, governance, release rules, and quality gates.

## Required product boundaries

- Public story metadata and browser-local demo state must be disclosed as prototype behavior.
- Reader interactions stay inside the app and preserve context.
- Brand treatments inherit registered HDS tokens and never leak across destinations.
- Story dates and bylines come from source metadata when available; the app does not invent them.
- Responsive verification includes 320px, 390px, tablet, and desktop widths.
