# AI-assisted workflows

This repository does **not** define seven autonomous Hearst Design System agents.
It currently defines project-wide instructions, two reusable project skills, and
two narrow helper-agent configurations. Token work, external-tool payload
generation, implementation, Storybook, QA, and release verification are workflow
areas performed by the active contributor; they are not separately installed
agents.

## Adding a project capability

1. Confirm the responsibility cannot be covered by `AGENTS.md`, an existing
   skill, or an existing script.
2. Add a narrowly scoped `.agents/skills/{name}/SKILL.md` with clear trigger
   language, inputs, guardrails, verification, and output expectations.
3. Add `.agents/skills/{name}/agents/openai.yaml` only when the skill needs
   discoverable interface metadata.
4. Add a helper-agent configuration only for a bounded task that can be safely
   delegated from the parent workflow.
5. Update this page from the committed files. Do not document an agent or skill
   before its configuration exists.
