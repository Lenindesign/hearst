## Generate the payload

```bash
npm run push-figma > figma-payload.json
```

The generator:

1. reads `tokens/core/global.json` and the 29 `tokens/brands/*.json` files;
2. creates one Variables collection;
3. creates publication modes, including the collection's initial mode;
4. converts supported colors, numbers, and strings to Figma values;
5. skips unresolved composite and reference values;
6. converts canonical hyphenated names to slash-grouped Figma names;
7. adds `codeSyntax.WEB` as `var(--canonical-token-name)`;
8. prints create actions and mode values as JSON.

The command does not inspect a destination file, update existing variable IDs, submit an API request, or confirm the result.

## Authorized write and verification

The external write must be performed through a team-approved Figma Variables API client or connected tool with the minimum required access.

After the write:

| Check | Pass criteria |
|---|---|
| **Destination identity** | The intended Figma file and collection revision are recorded without exposing credentials. |
| **Variable identity** | Canonical names map to the expected slash-grouped names without duplicates. |
| **Modes** | All expected publication modes exist and are named correctly. |
| **Values** | A representative core, semantic, component, color, number, and typography sample matches canonical Git values. |
| **Scopes** | Fill, text, stroke, spacing, radius, typography, and general scopes are appropriate for the token purpose. |
| **Code syntax** | The WEB syntax resolves to the canonical CSS variable name. |
| **Failures** | Unsupported values, API errors, skipped tokens, and partial writes are recorded. |

Payload generation is **Generated**. Only a completed destination check is **Verified in destination**.

## Designer usage

- Apply published variables instead of copying resolved hex, spacing, or typography values.
- Switch publication modes to review brand behavior.
- Use canonical names when discussing implementation.
- Compare component behavior and responsive states in Storybook and the routed application.
- File a canonical token change when a variable is missing or incorrect.

Do not edit Figma variables and assume the change will reach production. A Figma-only value is unshipped and can be overwritten by a later authorized delivery.

## Developer mapping

| Canonical Git name | Figma name | Production CSS |
|---|---|---|
| `palette-background-page` | `palette/background/page` | `var(--palette-background-page)` |
| `component-button-background-primary-solid-default` | `component/button/background/primary/solid/default` | `var(--component-button-background-primary-solid-default)` |
| `space-md` | `space/md` | `var(--space-md)` |
| `font-family-default` | `font/family/default` | `var(--font-family-default)` |

Figma grouping is a navigation aid. The canonical JSON key remains the cross-tool identity.

## Typography limitation

String variables can document font-family names and code syntax, but they do not prove that the font asset is installed, licensed, loaded, or applied correctly in Figma or production. Typography review must compare the actual publication font asset and rendered production component.

## Current gaps

- The generator creates payload objects with synthetic IDs; it does not reconcile them with an existing destination file.
- The repository does not store a non-secret receipt for the last successful Figma write.
- No automated round-trip comparison currently proves that every destination mode value matches canonical Git.
- Unsupported composite or reference values are skipped and require explicit coverage evidence.
- The Storybook page cannot confirm the current external Figma file or its revision without a connected, authorized read.

## Release rule

Figma delivery is not a production release. A token is production-ready only after canonical review, generated application output, quality gates, production component review, authorized publication, and exact-revision verification.
