Use the **Brand** toolbar to review shared components in another Hearst publication. Editorial cards, video cards, vertical-video carousels, navigation, and the reader modal update their HDS tokens and publication fixture together.

## Keep these integrated

- **Personalization console:** it explains and manipulates page-level ranking state.
- **Infinite river orchestration:** it coordinates hydration, ranked batches, the sentinel, and cross-destination feeds.
- **Games and destination pages:** they are templates made from reusable components, not library primitives.
- **Reader modal internals:** the modal depends on routes, focus restoration, source-article loading, related-story queues, and theme switching. Document it as an integrated story until those boundaries are extracted deliberately.

## Verified quality gate

Run these checks before publishing Storybook or changing a shared component:

```bash
npx tsc --noEmit
npm run test-storybook
npm run build-storybook
npm run build
```

The browser suite covers 98 stories and treats accessibility violations as failures. The production build remains a separate gate because Storybook deliberately uses compact static fixtures and blocks same-origin Next.js API calls instead of pretending its catalog is a live application server.

## Definition of done for a shared story

1. Imports the production component; it does not recreate the markup.
2. Uses current checked-in Hearst metadata from the generated fixture, or clearly labels an explicit interaction-state fixture.
3. Exposes meaningful behavior such as save, open, hide, carousel, or navigation state.
4. Works with the brand toolbar through semantic HDS tokens.
5. Covers keyboard focus and a 320px or 390px viewport when interaction is responsive.
6. Documents scoped exceptions instead of turning them into global variants.
