# Hearst+ personalization onboarding

This page specifies the onboarding that currently ships in Hearst+. The
canvases below mount the same `HearstOnboardingModal` component consumed by the
production homepage; they are not separate mockups.

## Production contract

| Step | Reader experience | Required state | Production action |
| --- | --- | --- | --- |
| Entry | A guest chooses **Sign in / Sign up** from the utility bar. | Reading remains available without a profile. | Open personalization or sign-in. |
| Interests | Choose one or two interests and see the feed preview update immediately. | One interest is required; two is the maximum. | **Continue** |
| Brands | Browse all configured publications and optionally strengthen trusted-brand signals. | No brand is required. Unavailable publications are disabled and explained. | **Use this feed** |
| Confirmation | Apply choices to the browser-local For You experience. | The reader can continue without an account. | **Continue without an account** |
| Account handoff | Save the same choices through the production account dialog. | This is optional and does not duplicate authentication inside onboarding. | **Save my feed** |

The current prototype stores personalization in the browser. Google-backed
profile sync depends on a configured, allowed application origin; it is an
account-integration boundary, not part of the onboarding component.

## Step 1: interests, limit, and live preview

The initial state communicates the one-of-two requirement, disables
**Continue**, and leaves enough room for the feed preview. Selecting a topic
updates the preview immediately; after two selections, the remaining choices

## State and accessibility coverage

| Concern | Spec and automated evidence |
| --- | --- |
| Empty | Preview prompt is shown and **Continue** is disabled. |
| Selected | Interest and brand buttons expose `aria-pressed`. |
| Maximum | After two interests, unselected interests are disabled. |
| Unavailable | Publications with no inventory are disabled and labeled “Unavailable in this demo.” |
| Optional | Brand selection is optional; anonymous completion remains available. |
| Focus entry | Every step moves focus to its heading. |
| Focus exit | Escape and close restore focus to the actual opener. |
| Keyboard | Focus is trapped inside the modal while it is open. |
| Screen reader | The dialog has a changing accessible name and description; step context and selection counts are announced. |
| Touch | Close, interest, footer, and primary actions meet a 44px minimum target. |
| Responsive | The direct mobile story checks width, overflow, selection, and target sizing. |

## Source and ownership

- Production component: `src/components/hearst-plus/onboarding-modal.tsx`
- Production consumer and account handoff: `src/components/home-page.tsx`
- Deterministic publication/story fixture: `src/stories/hearst-plus-story-data.ts`
- Interaction specification: `src/stories/HearstPlusOnboarding.stories.tsx`

Changes to the production onboarding must update these direct stories and this
contract in the same change. Do not recreate the flow with MDX-only controls or
invent requirements that are not present in the production component.
