# Technology

## A modern web stack built on the Hearst Design System.

This is a working reader prototype, not a static mock. The interface, ranking behaviors, responsive layouts, video playback, and route transitions run in the browser against live or cached content feeds.

## Application

### Next.js 16.1.6 + React 19.2.3

The experience uses the Next.js App Router for pages, server-rendered entry points, route handlers, image optimization, and React-powered interaction.

## Language

### TypeScript 5

Typed story, video, profile, and personalization models keep data contracts explicit across server and browser code.

## Interface

### Tailwind CSS 4 + HDS tokens

Tailwind handles responsive composition while Hearst Design System semantic tokens control shared surfaces, typography, color, spacing, and brand themes.

## Components

### shadcn 4.0.2 + Base UI 1.2.0

Reusable controls follow shadcn/ui composition conventions and use accessible Base UI primitives, with Phosphor supplying the icon set.

## Content

### Hearst feeds + Personalize

Server routes and the feed refresh pipeline combine public Hearst RSS story metadata with playable Personalize video recommendations, then the product applies eligibility and ranking rules. Storybook uses the checked-in result so component review remains deterministic.

## Delivery

### Netlify Next.js plugin 5.15.8

Production builds and Next.js server functions are deployed through Netlify's official Next.js integration, with optimized static assets served through its CDN.

### What “shadcn” means here

shadcn is not a hosted runtime dependency or a second design system. It provides the local component structure, aliases, and CSS-variable conventions recorded in `components.json`. The source lives in this repository under `src/components/ui/`, where Hearst tokens and product behavior remain reviewable. Headless behavior comes from Base UI where imported.

## Commands developers can rely on

```bash
npm run dev              # Next.js application
npm run build            # production Next.js build
npm run storybook        # Storybook on the configured local port
npm run build-storybook  # static Storybook validation
npm run feed:refresh     # import, enrich, and validate story inventory
npm run tokens:check     # verify generated token output
```

Build success does not authorize deployment. Commit, push, merge, and production publish remain explicit release actions.
