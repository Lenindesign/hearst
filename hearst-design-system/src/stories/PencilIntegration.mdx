## Appropriate uses

Pencil can help with:

- inspecting an existing `.pen` specification through supported editor tools;
- testing layouts or annotations that explicitly reference production components;
- reviewing canonical variables in a structured design file;
- recording a bounded handoff artifact when a team has chosen Pencil for that work.

Pencil must not be described as:

- the mandatory handoff layer for every component;
- automatically synchronized by running `npm run push-pencil`;
- pixel-identical to production without same-state, same-viewport comparison evidence;
- a replacement for production React, Storybook interaction tests, or responsive application review;
- the source from which canonical tokens should normally be regenerated.

## Generate the payload

```bash
npm run push-pencil > pencil-payload.json
```

The generator:

1. reads `tokens/core/global.json`;
2. reads the 29 publication-theme JSON files;
3. emits global variables as direct values;
4. emits brand-specific variables as themed arrays;
5. preserves canonical token names in the payload;
6. prints JSON to standard output.

It does not select a `.pen` file, call `set_variables`, save a design, validate layout, or compare the result with production.

## Authorized write and verification

Use the Pencil editor and its supported tools only after selecting the exact destination document.

| Check | Pass criteria |
|---|---|
| **Destination identity** | The exact `.pen` file is selected and recorded. |
| **Variable identity** | Canonical names exist without stale duplicates. |
| **Themes** | All intended publication themes exist and resolve predictably. |
| **Values** | Representative global, brand, component, spacing, and typography samples match Git. |
| **Layout impact** | Components using changed variables remain structurally valid. |
| **Production comparison** | Any parity claim uses the same production component, state, viewport, theme, and content. |
| **Save evidence** | The editor confirms the document was saved after the authorized write. |

The payload is **Generated**. Only a verified saved destination is **Verified in destination**.

## `.pen` handling

`.pen` files are editor-owned documents. Inspect or change them only through the Pencil tools; do not parse, rewrite, or merge their contents as ordinary source text.

The checked-in `homepage-version3.pen` is not referenced by `npm run push-pencil`, because that command only prints a payload. Any update requires an explicit destination selection and authorized editor action.

## Legacy and conflicting paths

The repository also includes:

- `scripts/sync-from-pencil.ts`, which reads the legacy `src/lib/pencil-variables.json` path and can regenerate application output;
- `scripts/sync-to-pencil.ts`, which fetches a separate Token Studio API and directly targets `../../hearst-brands.pen`.

These paths do not match the canonical Git-to-production workflow described here. They introduce a second upstream source or a different destination file and must be treated as legacy or migration utilities until the team explicitly documents their ownership, use case, and conflict resolution.

Do not use either path to overwrite canonical Git tokens or production output during ordinary component work.

## Component handoff rule

For a component to belong in the production design system:

1. production owns its React implementation and behavior;
2. Storybook imports that production component;
3. the story documents variants, states, responsive behavior, and accessibility;
4. canonical tokens own shared styling decisions;
5. a Pencil artifact, when present, links back to the production source and records any known divergence.

A design artifact can support the specification, but cannot substitute for a production import site or executable behavior.

## Current gaps

- No repository-owned receipt records the last successful Pencil variables write.
- The payload generator does not identify or verify a destination `.pen` file.
- The active checked-in `.pen` file and the legacy direct-write target are different files.
- No automated comparison proves that Pencil variables or components match production.
- Legacy Pencil-to-code scripts can imply bidirectional authority that conflicts with canonical Git tokens.
- Ownership and deprecation dates for the legacy scripts are not recorded.

## Release rule

A saved Pencil file is not a production release. Production readiness requires canonical review, generated application output, executable Storybook evidence, application quality gates, and verification of the published artifact's exact source revision.
